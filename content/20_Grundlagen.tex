\section{ATLAS aus Anwender-Sicht}
In diesem Abschnitt wird ATLAS aus Sicht der Anwender beschrieben. Technische Details werden hier bewusst nur kurz angesprochen und in Kapitel 3 aus Entwickler-Sicht genauer erklärt.
ATLAS ist eine Webanwendung, die auf einem Angular-Frontend und einem .NET-basierten Backend aufbaut. 

Aus Anwender-Sicht dient ATLAS als Plattform zur Dokumentation von Laser-Applikationen und Versuchen. Die saubere Verarbeitung der Daten ist besonders wichtig, da fehlerhafte oder unvollständige Daten direkte Auswirkungen auf Anwendungsentwicklung und Kundenberatung haben können. Aus diesem Grund ist der Aufbau einer stabilen Testinfrastruktur ein zentraler Bestandteil des Projekts: neue Funktionen sollen schneller bereitgestellt und gleichzeitig zuverlässig abgesichert werden.

\subsection{Softwaretests im Überblick}
Darzustellen sind zentrale Testarten (Unit-, Integrations- und End-to-End-Tests) sowie die Testpyramide als Modell für eine ausgewogene Teststrategie.
Als methodische Grundlage dienen standardisierte Testprozesse \cite{IEEE29119_2_2021} sowie das Testpyramiden-Modell zur Gewichtung der Testebenen \cite{Cohn2009}. Für die Isolation von Komponenten in Unit-Tests ist die klare Trennung von Test Doubles zentral \cite{Fowler2007}.

\subsection{Azure DevOps und Azure Blob Storage}
Zu erläutern sind Build- und Pipeline-Funktionen in Azure DevOps sowie die Rolle von Azure Blob Storage für Artefakte oder Testdaten.
Azure Pipelines unterstützt mehrstufige CI/CD-Prozesse und automatisierte Testausführung \cite{MicrosoftAzurePipelines2026,MicrosoftAzurePipelinesArchitecture2026}. Für testspezifische Blob-Storage-Szenarien kann Azurite als lokaler Emulator eingesetzt werden \cite{MicrosoftAzurite2026}.

\subsection{Visual Studio}
Visual Studio ergänzt die Testinfrastruktur durch Test Explorer, integrierte Ausführung und Analyse von Tests sowie zusätzliche Qualitätssicherungswerkzeuge \cite{MicrosoftTestExplorerBasics2026,MicrosoftTestingToolsOverview2026}.
Im Projekt wird Visual Studio insbesondere für die Backend-Entwicklung genutzt, um Tests zu implementieren, auszuführen und systematisch auszuwerten. Der zentrale Mehrwert liegt in der integrierten Unterstützung für Unit-Tests, Code-Coverage-Analysen und testbezogene Auswertungen über den Test Explorer.

\subsection{Angular}
Hier wird Angular als Frontend-Framework eingeordnet, insbesondere im Hinblick auf testbare Komponenten und UI-Interaktionen.
Für das Testen sind insbesondere Angular TestBed sowie die standardisierte Einbindung von Jasmine und Karma relevant \cite{AngularTestingKarma2026,JasmineDocs2026,KarmaDocs2026}.

\subsection{Docker}
Optional kann Docker als Containerisierungsansatz für reproduzierbare Testumgebungen dargestellt und begründet werden.
Docker und Docker Compose ermöglichen reproduzierbare Multi-Container-Testumgebungen für lokale Entwicklung und Pipeline-Ausführung \cite{DockerDocs2026,DockerComposeSpec2020}. Ergänzend zeigen aktuelle Arbeiten die Eignung von Containeransätzen für skalierbare Testlabore \cite{Lemos2026}.

\subsection{.NET Core}
Darzustellen sind die für die Backend-Tests relevanten Eigenschaften von .NET Core, etwa Testintegration und Ausführbarkeit in CI-Umgebungen.
ASP.NET Core stellt hierfür etablierte Muster für Unit- und Integrationstests bereit, einschließlich testbarer Servicearchitekturen und In-Memory-Testservern \cite{MicrosoftTestingASPNETCore2026,MicrosoftTestASPNETCoreMVC2026}. Ergänzend sind Best Practices zur Teststruktur und Wartbarkeit zu berücksichtigen \cite{MicrosoftUnitTestingBestPractices2026}.

\subsection{Frameworks}
Die folgenden Frameworks bilden die technische Grundlage für den Testansatz der Arbeit.



\subsubsection{xUnit}
xUnit eignet sich als etabliertes Framework für Unit- und Integrationsnahe Tests im .NET-Umfeld.
xUnit ist im .NET-Umfeld weit verbreitet und eng mit etablierten Testpraktiken in ASP.NET-Core-Projekten verbunden \cite{xUnitDocs2026,MicrosoftUnitTestingBestPractices2026}. warum x unit? und niccht n unit oder mstest?

\subsubsection{Playwright}
Playwright wird für browsernahe End-to-End-Tests eingesetzt. Bei knapper Seitenzahl kann auf offizielle Dokumentation verwiesen werden.
Playwright unterstützt stabile, browserübergreifende E2E-Tests mit einheitlicher API und CI/CD-Integration \cite{PlaywrightDocs2026}.
